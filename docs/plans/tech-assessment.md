## 1. 結論

1. **手書き 1 問の制作は、計画の 0.5 h より桁違いに小さい。** 短信 5 画面分のデータ + 異変 1 つ + 答え合わせの文面を作るのに、外で確かめられる上限で **2 分 34 秒** (測った、n = 1、AI が作成)。0.5 h の **1/11 未満**。ただし、画面の描画・企業名の衝突の確認・一次資料での確認・レビューの往復は含まない (別の項目で、置き換えていない)。**案 B の資料束 (短信 + IR スライド 5 枚 + 資料間の矛盾 1 つ) も測った**(#14): 外で確かめられる上限 **6 分 9 秒** = 計画の資料束 1.0 h の 0.103 倍 (約 1/10)。IR 側を短信の 2 倍と置いた仮定は、測った値に置き換わった。
2. **生成した正常データが会計の整合を満たすことは、測れる範囲で満たした。** 1 期分の連結 3 表 + サマリーを導出の順序で作ると、整合 (67 規則: 貸借の等式・損益の連鎖・CF の連動・比率・表示値どうしの別経路の突き合わせ) を **1 回目で 100%** (N = 20,000)。素朴な独立乱数は 0%。→ plan-comparison §3.3 のリスク「整合を満たせるかが未測定」は、**コアの範囲では「満たせる」に変わった**。範囲外 (注記・IR 側の生成・資料間の矛盾の生成・25 種類) は未測定。規則の網羅は、一次資料 (作成要領・財務諸表等規則) との突き合わせで確かめられる範囲があり、人に頼むかは open-decisions Q1 (確認の水準) で決まる (未確認)。
3. **案 B と案 C の総工数の順位: plan-comparison §6 が書いた逆転 (手書きが 2 倍以上遅い) は起きない (測った)。** 手書きは計画の 1/11 以下で、2 倍どころではない。**ただし、手書きと生成の両方を小さくすると、B と C の差は「測っていない項目の仮定の差」だけに収まり、符号は決まらない (未確認)**: 分解すると約 4 h (総工数 約 110〜120 h の 4% 未満) で、その符号は、計画が置いた「生成の規則の確認 G10 = 8 h、手書きの確認 B9 = 12 h」(どちらも測っていない) から来る。なお、この総工数は**測った項目と計画の仮定の項目を混ぜた尺度で、絶対値としては使えない**。G10 を 12 h にすると差は −1.5 h、16 h にすると +4.5 h と符号が入れ替わる (§3.2)。→ **総工数の大小で B と C を分けることはできない (同点)**。推奨 (案 B) の導出は工数の大小に依らない (§6 の 1・2・5) ので、**推奨は変わらない**。ただし導出の 3 (取り消しの費用)・4 (実現性が未測定) は弱まる (§3.3)。
4. **新しく分かった技術のリスク 3 つ** (§5): 生成の式と検証の式が同じ出所だと同じ誤りを見落とす (配当性向を公式でない式で作ったまま検証が通っていた。JPX 作成要領 p.27 の式に直した。公式の式でも、遊び手の別経路の検算 (配当金総額 ÷ 純利益) とは 0.41% でずれる)・貸借や CF の 1 項目を変える異変は 2 本以上の規則を同時に壊す (単独の異変にするには下流の再計算が要る)・「正常だが異変に見える」書き方 (特別損失など) は一次資料での確認でしか拾えない。
5. **見積もりの尺度**: 測った時間は組(進める役)の作業時間で、計画の h と同じ単位。ただし、測っていない項目 (基盤・テンプレート・B9/G10・B10/G11 など) の仮定は、人間の作業のような速さで置かれていて、測った項目 (手書き・生成) と 10 倍以上ずれている。測るか、同じ倍率で置き直すかを決める必要がある (§6)。レビューの往復は、制作に対して 1.4〜1.9 倍かかった (#10 は自己申告の制作で 1.36、#9 は外上限で 1.9。n = 2、区間に重なりあり。§4)。計画の係数 1.5 (往復 = 実装の 5 割) より重く、制作 + 往復は約 2.4〜2.9 倍。

## 3. 案 B と案 C の逆転の判定

### 3.1 plan-comparison §5・§6 の条件

§6: 「手書きの制作が想定の 2 倍以上遅く、かつ生成した正常データが会計の整合を満たすと測れたとき、案 C の総工数のほうが小さくなりうる」。

- **前半 (手書きが 2 倍以上遅い): 満たさない**。短信 1 問の上限 2 分 34 秒 ÷ 計画 0.5 h = 0.086 倍 (測った / 導いた)。2 倍を否定するには 1 問全体の上限が要るというレビューの指摘に従い、サマリーだけでなく 5 画面分で測った。**資料束 (IR 側を含む) も測った**: 6 分 9 秒 ÷ 1.0 h = 0.103 倍 (#14)。
- **後半 (生成が整合を満たす): 満たす** (コアの範囲。§2 #2)。
- **判定: 条件の前半を満たさないので、§6 が定義した逆転は起きない**。

### 3.2 別の経路: 手書きと生成を小さくすると、差は測っていない仮定だけになる

`spike/reversal.py` (estimate.py を読み込み、問題制作 B5〜B8 と生成まわり G5〜G9 だけを縮める。一次資料の確認 A8・B9・G10 は縮めない。plan-comparison の estimate.py の scale_content は確認も縮めるため、ここでは別に出した)。`cd docs/plans/spike && python3 reversal.py` で再現できる。

- 計画の仮定のまま: 案 A 102.2・案 B 159.8・案 C 178.2 h (総工数)。
- 手書きだけを測った値 (s = 0.10。短信 0.086・資料束 0.103 の上側を丸めた) に置き換えると: 案 A **82.0**・案 B **119.2**・案 C 178.2 (C − B = +59.0 h)。
- **生成が計画どおり (t = 1) なら、B が C を超えるのは、資料束 1 問の単価が 1.41 h を超えるとき** (導いた: s > 1.41)。資料束 1 問の測った上限は 0.103 h (6 分 9 秒) で、逆転に必要な 1.41 h の **約 1/14** (測った + 導いた)。
- 生成の倍率 t を動かす (s = 0.10 固定、K = 1.5):

| t (G5〜G9 の計画に対する倍率) | 案 B (総工数 / パス) | 案 C (総工数 / パス) | C − B |
| --- | --- | --- | --- |
| 1.0 (計画のまま) | 119.2 / 60.2 | 178.2 / 98.0 | +59.0 |
| 0.3 | 119.2 / 60.2 | 131.0 / 66.5 | +11.8 |
| 0.126 (境目) | 119.2 | 119.2 | 0 |
| 0.1 | 119.2 / 60.2 | 117.5 / 57.5 | −1.8 |
| 0.015 | 119.2 / 60.2 | 111.8 / 53.7 | −7.5 |

- **t < 0.126 で C が下回るのは、生成が速いからではない** (レビューの指摘 B1)。s と t を 0 に近づけると、C − B は共通の Task が打ち消し合い、測っていない項目の仮定の差だけが残る (導いた。`reversal.py` の (5)): G3 − B3 (会社の設定と衝突の確認) **+1.5** + G10 − B9 (一次資料での確認。G10 = 8 h × 1.5、B9 = 30 問 × 0.4 h × 1.5) **−6.0** + Task の包括レビュー (C は B より 1 件多い) **+0.5** = **−4.0 h**。つまり境目 0.126 は、計画が「生成の規則の確認 G10 は 8 h、手書きの確認 B9 は 12 h」と置いた仮定から来ている。**どちらも測っていない** (§5 の 3 で、一次資料での確認の単価は今回の測定で置き換わらないと書いた)。
- G10 だけを動かすと符号は入れ替わる (s = 0.10・t = 0.015 のまま): G10 = 8 h で C − B = **−7.5**・12 h で **−1.5**・16 h で **+4.5**。
- t の導出 (参考。**導いた、大きな不確かさ**): 試作が覆った範囲の計画時間を、G5 の約半分 (0.5 × 12 h) + G9 の約 8 割 (0.8 × 8 h) + 注入 6 種類 (6 × 1.0 h) = 約 18 h と数え (覆った割合は本ページでの判断で、**仮定**)、試作の経過 約 13 分 (0.22 h)〜外で確かめられる上限 16 分 55 秒 (0.28 h) で割ると **0.012〜0.016**。範囲外 (注記・IR 側・資料間の矛盾・19 種類の注入・G4・G10) の単価は、範囲内より重い可能性が高いので、**t の値で順位を決めない**。
- 測った値と測っていない仮定の混在: s と t は測った値だが、B9・G10・G3・G4・K・テンプレート・基盤は測っていない仮定のまま (§6 の測っていない項目の扱い)。この混ぜた総工数は絶対値として使えず、その上で出した符号は、どちらの案の優劣の根拠にもならない。
- K を 2.0・2.9 にしても (§4)、t = 0.1 で C − B は −2.5・−3.9、t = 0.3 で +15.5・+22.2 h で、境目はほぼ同じ (t ≈ 0.1)。

### 3.3 判定と推奨への影響

- **判定**: (1) §6 が書いた逆転 (手書きが 2 倍以上遅い) は **起きない (測った)**。資料束 (IR 側を含む) も測っており、逆転に必要な 1.41 h に対して測った上限は 0.103 h。(2) 手書きと生成の両方を小さくした場合の B と C の差は、約 4 h (総工数の 4% 未満) の**測っていない仮定の差**に収まり、**符号は決まらない (未確認)**。確かめるには、一次資料での確認の単価を案ごとに測る必要がある (§6 の起票案 3)。
- **推奨 (案 B) の導出** (plan-comparison §6) への影響:
  1. 「人間の言葉を満たす案に絞る」→ 変わらない (案 A を既定にしない理由)。
  2. 「案 C の違いは問題の作りかただけ。無限に出せるのは人間が言っていない価値判断」→ 変わらない。
  3. 「取り消しの費用が非対称 (失敗時に 79.5 h を捨て 63 h を足す)」→ **弱まる**。整合が満たせない可能性は、コアの範囲では下がった (測った)。ただし損失の大きさ (h) は単位が変わると縮み、範囲外 (注記・資料間の矛盾) は未測定。
  4. 「技術の実現性が未測定」→ **コアの範囲では解消**。残る実現性の未測定は、注記・IR 側の生成・資料間の矛盾の生成・規則の網羅 (一次資料との突き合わせ。人に頼むかは Q1)・「作り物らしさ」(好み)。
  5. 「規模の参照 (先行例 約 2.5 日・2 者で 41 問)」→ 変わらない。
- したがって**推奨は、工数の大小でも実現性でもなく、1・2・5 (人間の言葉に無いものを買わない) に依る**。人間に案を問う文面に「測ると案 C のほうが工数が小さくなりうる」とは書けない (符号は測っていない仮定の差)。責任者が推奨を維持するか、案 C の利点 (問題が尽きない) を人間に問うかは、責任者の判断。

## 5. 新しく分かった技術のリスク (測った)

1. **生成の式と検証の式が同じ出所だと、同じ誤りを見落とす** (測った)。初版〜2 版は、サマリーの配当性向を「配当金総額 ÷ 純利益」で作っていた。#10 のレビューが、遊び手の検算 (1 株当たり配当金 ÷ EPS) との 0.1 pt のずれ (0.37%) を見つけ、検証に別経路の突き合わせを足して棄却で引き直す方針にしていた。ところが **#14 で JPX 作成要領 (2026 年 7 月版) の p.27 を読むと、公式の式は「配当性向(連結) = 1 株当たり個別配当金(合計) ÷ 1 株当たり連結当期純利益 × 100」(分母がマイナスなら「-」) で、総額 ÷ 純利益は公式の式ではなかった**。→ **表示は作成要領の式で作る**ように直した (gen.py)。これで 20,000 件が 1 回目に 100% 通る(棄却は不要)。公式の式で作っても、遊び手が表示された「配当金総額 ÷ 純利益」で検算するとき、配当がある 16,647 件のうち 69 件 (0.41%) で 0.1 pt ずれる(四捨五入のため)。これは**遊び手の別経路のリスクとして残る** (soft 規則に降格。答え合わせの文面で扱う)。手書き (案 B) も同じ別経路のずれがありうる。取得の手順: `curl -sS -o sakusei.pdf <research.md §2.1 の URL>` で HTTP 200 (2,165,223 B・66 ページ)。WebFetch ツールでは 403 だったので、前の版の「PDF は 403 で未確認」は取得手段の選び方の誤りだった (`spike/README.md`)。
2. **異変の注入は、1 つの数字を変えるだけでは単独の異変にならない** (測った)。正常データの 1 項目を +1 すると、検証が検出するのは 100% (6,000/6,000)、ただし落ちる規則が 1 本だけになるのは 25% (サマリーの比率 70%・損益 45%・貸借 8%・CF 4%)。貸借・CF を書き換える 3 種類の注入は、最初の版では想定外の規則が 3〜6 本落ちた (サマリーに漏れた)。サマリーを再計算する関数を足して 6 種類とも想定どおり (200/200)。→ 25 種類の異変は、**種類ごとに「どの規則だけを落とすか」を決め、下流を表示上つじつまが合うように再計算する作業が要る**。計画の「異変の注入 1 種類 1.0 h」は、貸借・CF の異変では妥当か、やや軽い (見立て。6 種類の実績: inject.py 約 100 行)。
3. **「正常だが異変に見える」書き方が、規則の外にある** (見立て)。例: 特別損失を現金払いとして整合させているが、減損・除却損と読む遊び手は CF に足し戻しが無いことを異変と判断する。生成の検証 (整合) では拾えず、一次資料での確認 (A-A8・B9・G10) でしか拾えない。→ **一次資料での確認の単価 (0.25〜0.4 h/問) は今回の測定で置き換わらない**。確認の水準 (オーケストラが一次資料で確認するか、人に頼むか) は open-decisions Q1 で決まる。

4. **資料間の矛盾の異変は、比べる相手の定義で正常に見えうる** (見立て。#14 のレビューの申し送り)。hand-q01-ir-anomaly.json の「IR の設備投資 580 と短信 CF の取得による支出 850」は、IR スライド 4 の当期実績 850 とも食い違うので答えが 1 つに決まる。ただし実在の IR の「設備投資」は計上ベースのことが多く、CF の支払ベースと一致しないのが普通で、短信とだけ比べる形にすると、会計の分かる遊び手には正常に見えうる。製品の資料間の矛盾は、同じ定義の数字どうし (例: 売上高、営業利益、セグメントの合計) で作る。
5. **株数が 1 つだけの試作では、BPS の分母の違いが出ない** (見立て。同じ申し送り)。作成要領のサマリーには期末発行済株式数・期末自己株式数・期中平均株式数が別々に出る (p.22 の様式)。gen は BPS も期中平均株式数で割っている。製品で株数を分けて表示するときは、BPS を期末の株数 (自己株式を除く) で作る必要がある。
