## 3. 会社別の数字の方針 (#70 で作る正常な資料)

- **期は過去にする**: 25 問のすべてで、発表日が公開の日 (2026-11) より前になる期 (2023〜2025 年の決算期。見本は 2023 年3月期) にした (レビュー N2)。未来の日付の発表日は、E-04 (期・日付の食い違い) を覚えた遊び手に、正常な問題が異変に見える。
- **同じ会社の期は続けて作る**: 会社ごとに 1 本の時系列 (前の期の当期 = 次の期の前期) で作る。同じ会社を何度か見た遊び手の記憶と数字が食い違わない (レビューの提案)。
- **特別利益は、現金で受け取り資産が動かないもの** (受取保険金・補助金収入など) に限る (anomalies.md G5: 有形固定資産の売却・除却・減損は無い。固定資産売却益は使わない。特別損失と同じ扱い)。

- 規模・利益率・自己資本比率などの目安は companies.md §5.1 に従う。**やさしいの資料は非支配株主持分を 0 にする** (anomalies.md E-16: 純資産合計 ÷ 株式数で確かめた遊び手が正常を異変と答えないため)。
- 売上高の増減率は ±15% 以内 (検証器の参考の規則 soft-sales-growth-range は ±20%)。実効税率は 25〜40%、営業利益率は −5〜25%、自己資本比率は 20〜80% など、参考の規則の範囲に収める (正常な資料は参考の規則も報告ゼロにする)。
- 要素のある年の翌年は、利益の戻りを許す (利益の増減率 ±20% の制限を外す)。異変の問題 easy-005・easy-022 には、前の期の要素 (特別損失・大きな減益) からの戻りとして大きな増減がある。答えは「あり」で判定は変わらない。
- 換算差額は全社 0、無形固定資産・のれんは置かない、長期借入金は直接増減する (anomalies.md G4・G5)。科目名は全社で汎用 (G11)。
- IR の単位が億円の会社 (c03・c05・c06・c08・c10) は、短信の百万円 ÷ 100 を小数第一位まで四捨五入した値を IR に書く。IR の中の式 (純有利子負債など) は、表示値どうしで完全に一致する値を選ぶ (design §4.1)。
- IR の口調は会社ごとの設定 (companies.md §5.3) に従う。IR の文章には、**主張が数字と一致する文だけ**を書く (`ir.statements` の `claims` で示す)。

## 3.1 段の割り当ての理由 (レビュー N4)

段 1 の異変は毎回の 1〜2 社目に出て (出会う回数の 43%)、戻されるたびに再挑戦になるので、**知識や多くの足し算が要る種類を置かない**。E-09 (4 つ以上の足し算。検算は 2 つの数の差・比しか出さない) と E-06 (グラフの作法の知識) は段 2。段 1 は、見比べるだけで分かる E-01・E-02・E-04・E-08・E-17 と、1 回の引き算で分かる E-10。

## 4. 見本 (P0)

- c09 キュルネ教育 2023年3月期 (正常、疑わしく見える要素なし)。`anomaly: null`。**プールの外**に 1 つ置き、やさしい・むずかしいで共有する (experience.md §6.3 の 6)。置き場は `src/data/samples/sample.json` (技術の見立ての形 `{ problem, notes }`。notes は 画面 ID → 注釈の文)。
- 注釈は、画面ごとに 1 文で、確かめた整合を述べる (例: 「貸借対照表: 資産合計と負債・純資産合計が一致しています」)。

## 5. 確かめ方

- 検証器 (`npm run verify:data`、ブランチ calliope/validator) を全問に当てる: 正常な問題は 規則の違反ゼロ (参考の規則の報告もゼロ)、異変の問題は 期待集合 = 実際に落ちた集合 ⊂ 許容集合。数が足りない (`shortfalls`) が空。
- E-08 (社名・証券コードの食い違い) は、社名を 1 字違いにすると実在の社名との照合が要る (`check_names.py` は元の社名にしか当てていない) ので、**証券コードの下 2 桁の入れ替え** (0804 → 0840) にした。0840 は会社の設定に無い架空の帯の値で、実在の証券コード (1301 以上) と重ならない (companies.md §3)。
- `gen.py` は同じ spec.json から同じ JSON を作る (乱数は問題 id から作った種)。
