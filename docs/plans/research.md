### 2.2 決算説明資料 (IR 資料)

決算説明資料 (投資家向けスライド) の構成は、取引所の定型様式がなく、会社ごとに違う。これは調べて「定型が見つからなかった」ので、**未確認** (試したこと: 作成要領の検索で定型様式が出ないことの確認のみ。個別会社の資料は、実在企業を使わない方針と、資料の再現が目的でないため調べていない)。ゲーム用の構成は、本プロジェクトで自由に決める (仮定)。

### 2.3 異変にできる整合性の決まり (会計の等式と、粉飾の典型)

| 異変の種類 | 内容 | 印 | 出典 |
| --- | --- | --- | --- |
| 見た目の異変 (誤植・桁・単位・符号・百分率) | 同じ数字の 2 か所の食い違い、単位 (百万円と千円) の取り違え、増減率の符号 | 導いた (会計の知識が要らない種類。出所は本プロジェクトの定義) | |
| 計算の異変 | 合計が内訳の和と合わない。増減率が前期比の数字から計算した値と合わない | 導いた (四則演算で確かめられる) | |
| 貸借対照表の等式 | 資産 = 負債 + 純資産 | 文書にある | [会計の基本解説](https://www.vjmglobal.com/ja/blog/understanding-financial-statements-connections) の等式の説明 (検索結果から) |
| 損益と貸借対照表・キャッシュ・フローの連動 | 純利益は貸借対照表の利益剰余金とキャッシュ・フロー (間接法の起点) に連なる。期首の現金 + 増減 = 期末の現金で、貸借対照表の現金と一致する | 文書にある | 同上 (検索結果から) |
| 利益と現金の乖離 | 利益が増えているのに営業キャッシュ・フローが減る、売掛金だけが伸びる、というのは粉飾の兆候として確認される | 文書にある | 同上 (検索結果から) |
| 会計の異変 (むずかしい向け) | 売上の過大計上・前倒し、架空仕入れ・原価操作、在庫数量の水増し、実体のない取引 | 文書にある | [sbbit (2025-08)](https://www.sbbit.jp/article/refers/169967)・[税経新報 会計不正の構造 file 08](https://www.zeiken.co.jp/keieizaimu/article/no3258/ZA00032581201.php)・[同 その 3](https://www.zeiken.co.jp/keieizaimu/article/no3635/ZA00036351701.php)・[同 その 6](https://www.zeiken.co.jp/keieizaimu/article/no3647/ZA00036471601.php) |
| 粉飾の統計 | 2024 年度に不正を公表した上場企業は 56 社 (約 4 年前の 2 倍)。粉飾の手口は「架空仕入れ・原価操作」と「売上の過大計上」が多い | 文書にある (二次資料。JICPA の一次報告は未取得) | [sbbit](https://www.sbbit.jp/article/refers/169967) |
| 注記・継続企業の前提・監査意見の異変 | 注記の矛盾、継続企業の前提の注記と財務数値の食い違いなど | 未確認。試したこと: 検索 1 回で該当情報が出なかった | |

使いみち: 「やさしい = 見た目 + 計算」「むずかしい = 会計」(要件) は、上の表の上 2 行 / 下の行に対応づけられる。むずかしい向けの会計の異変は、実際の事件を再現せず、一般的な手口を架空の会社に当てはめる (仮定。実在の事件を使うと実在の企業・人物に触れるおそれがある)。会計の異変は、遊び手に簿記・財務分析の知識を求める。その前提知識の水準 (想定する遊び手) は要件で人間が決める。

## 3. 公開 (Vercel の静的サイト) の制約

要件: 公開する場所は Vercel の静的サイト (Q3 の選択 1)。費用は 0 円 (無料枠の範囲)。

| 事実 | 印 | 出典 |
| --- | --- | --- |
| Hobby チームは「非営利の個人利用」に限られる。営利利用は Pro 以上が必要 | 文書にある | [Vercel: Fair Use Guidelines](https://vercel.com/docs/limits/fair-use-guidelines) (更新 2026-09-14) |
| 営利利用の定義: 制作に関わった「誰か」の金銭的利益を目的とするデプロイ。支払いの受付・広告の掲載・サイトの販売の宣伝・サイトの制作や運営の対価を受けること・アフィリエイトが主目的、など。広告 (AdSense など) を載せると営利。寄付の依頼は営利に当たらない | 文書にある | 同上 |
| 判断に迷うときは Vercel のサポートに問い合わせる | 文書にある | 同上 |
| 月の目安 (Hobby): 高速データ転送 最初の 100 GB、関数呼び出し 100 万回、Active CPU 4 時間 など | 文書にある | 同上 |
| 静的ファイル (index.html など) の配信はビルドに数えない。1 時間 100 回・1 日 100 回のデプロイ上限がある | 文書にある | [Vercel: Limits](https://vercel.com/docs/limits/overview) (更新 2026-09-16) |
| 1 回のビルドは最大 45 分。Hobby の同時ビルドは 1 | 文書にある | 同上 |
| Hobby の上限を超えると 30 日待つ必要がある | 文書にある | [検索結果の要約](https://vercel.com/docs/plans/hobby-plan) (一次ページの全文は未取得) |
| Hobby のプロジェクトは、Git の組織 (organization) が所有するリポジトリに接続できない | 文書にある | [Vercel: Limits](https://vercel.com/docs/limits/overview) |
| calliope-pro は組織でなく個人 (User) のアカウント。Hobby でも Git 連携できる | 測った (`gh api users/calliope-pro` の結果: `User`、2026-11-03) | |
| このゲームを無料で公開する場合は営利に当たらない | 導いた (上の営利の定義と、要件の「費用 0 円」から。広告・課金・対価を受ける運営が無い前提) | |
| 転送量の見積もり: 1 人が 1 回遊んで運ぶ量を 3 MB、月 1 万回遊ばれると 30 GB (100 GB の 30%) | 仮定 (3 MB は静的サイトの軽い想定。測っていない。実装の後に測る) | |

営利になる条件 (広告・課金・制作の対価を受けるなど) を要件に入れるなら、Pro が要る。費用 0 円の前提と衝突するので、人間が決める事柄になる。
