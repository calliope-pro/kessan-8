## 1. 要約

- 異変は **45 種類** (要件・受け入れ条件は 25 種類以上)。**やさしい 17** (見た目 8・計算 8・文章 1) と **むずかしい 28** (会計 13・資料間 9・注記 4・手口 2)。**問題に使うのは 42 種類** (やさしい 17・むずかしい 25)。H-25〜H-27 (確度 C) は責任者の決定で使わない。
- **系統と難易度**: 系統の名前と難易度の対応は docs/design.md §4.5 の `FAMILY_DIFFICULTY` が正本 (見た目 appearance・計算 calculation・文章 text = やさしい、会計 accounting・資料間 cross-document・注記 notes・手口 tactics = むずかしい)。出題の「多め」の閾値は、やさしい = 見た目 + 計算が異変の問題の 8 割以上、むずかしい = 会計 + 資料間が 6 割以上 (設計。検証器が確かめる)。
- **系統「文章」(E-17) をやさしいに置く解釈**: 要件 6 は「やさしい = 見た目と計算」。E-17 は、同じ資料の文章と数字の符号を見比べるだけで見つかる (知識なしで、読んで比べる)。要件の趣旨「知識なしで読む・計算するだけで見つかる」に入ると解釈し、少数 (1 種類) にとどめる。
- 種類ごとに、どの画面のどこが・どう変わるか・破れる規則・適する会社・答え合わせの説明文の型・正常の条件・根拠を書いた (§6)。
- 1 つの異変は **1 つの原因 (1 つのセル・1 つの文・1 つの図) の変更**で、種類ごとに「主な規則」と「付随して落ちてよい規則」を決める。検証器が、全問で「落ちた規則が空でない・主な規則を含む・許容集合に収まる」ことを確かめる。正常な資料は、会計の整合 (貸借の一致・損益の連鎖・キャッシュ・フローの連動・主要な比率) をすべて満たす (charter の失敗 1・2 への手当て。§3 の G1〜G9)。
- 境界の判断が入る 3 種類 (H-25〜H-27) は確度 C とし、責任者の決定により問題に使わない (確認が済んで使うときは、規則を足すチケットを切る)。それを除いても、難易度ごとに 25 問以上を作る材料がある (§7)。
- 比率・定義の根拠は、JPX の作成要領 (2026 年 7 月版) の原文のページで確かめた (§8)。

## 3. 作りかたの決まり (全種類に共通)

| 番号 | 決まり | 理由・根拠 |
| --- | --- | --- |
| G1 | **1 つの異変は、1 つの原因 (1 つのセル・1 つの文・1 つの図) の変更**。ある数字が 2 つ以上の等式の入力になっているとき (買掛金は貸借と CF の連動の両方、など) は、2 つ以上の規則が同時に落ちる。そこで、各種類の「破れる規則」を、**主な規則** (その種類を定義する規則。1 つ) と、**付随して落ちてよい規則** (同じ原因で必然的に落ちる規則) に分け、この文書を正とする。問題データには、種類の ID と、変えたセル (または文・図) を持たせる。検証器は全問で、次の 3 つを確かめる: (1) 落ちた規則の集合が**空でない**、(2) 主な規則が落ちた集合に**含まれる**、(3) 落ちた集合が「主な規則 + 付随して落ちてよい規則」(許容集合) の**部分集合**である。許容集合に無い規則が落ちた問題は、意図しない不整合として出題しない。付随する規則の書き漏れは、検証器を作る Task が許容集合に足す。数値でない種類 (E-03〜E-08・E-17・H-21・H-22・H-24・H-26〜H-28 など) の主な規則は、体裁・文章・パターンの規則 (検証器の別の種類の規則) とする。**T2 の数字を変えて合計を再計算する種類 (H-01・H-02・H-09・H-10 など) では、T1 の対応する値 (総資産・純資産・自己資本・自己資本比率・自己資本当期純利益率・1 株当たり純資産) も、変えた T2 から再計算して揃える** (揃えないと「表示-サマリーの値」の規則が落ち、許容集合に無いので問題が弾かれる) | charter の原則「テスト容易性」「失敗 1・2」。落ちる規則が 0 個の問題 (異変「あり」が正解なのに画面に異変が無い) を、(1) で防ぐ。試作の注入実験 (docs/plans/spike/inject.py) も、6 種類のうち 4 種類で 2 つの規則が落ちた (INJECTIONS の想定の集合) |
| G2 | **正常な資料は、整合の規則をすべて満たす**。合計は内訳の和と完全に一致させる (表示値から再計算)。端数は、サマリー・表では百万円未満切捨て、% は小数第一位未満を四捨五入、銭は銭未満を四捨五入 | 作成要領 p.24「端数等の処理」(文書にある)。切捨てのときに生じうる ±1 の差は、正常の資料では出さない (設計) |
| G3 | **異変のずれは、端数で説明できない大きさにする**。「対象値」は、**変えた項目の変更前の値**。金額 (百万円) は 5 百万円以上かつ対象値の 1% 以上、億円の金額 (IR。G8 の丸め) は 0.3 億円以上かつ対象値の 1% 以上、% は 1.0 ポイント以上 (H-11 だけは 0.3 ポイント以上。H-11 の節)、円・銭の指標は対象値の 1% 以上。これより小さいずれは異変にしない | 端数処理で正常でも出うるずれ (±1 百万円、±0.1 ポイント、億円の小数第一位の丸め ±0.05 億円) と見分けるため。閾値の値は設計 |
| G4 | **キャッシュ・フロー計算書は日本基準に合わせる** (T1 の表題に〔日本基準〕を必ず出す)。営業活動は税金等調整前当期純利益から始める。財務活動の長期借入金は、収入と支出を総額で別の行に出す (純額で 1 行にしない)。資金の範囲を T4 に注記し、期末残高はその範囲の貸借対照表の額と一致させる。換算差額の行は**全社で 0 (「―」)** を表示する。外貨 (c01 の海外売上、c10 の輸入) は文章でだけ触れる。G5 の単純化のもとで連動の規則をすべて満たすと、資産の増加 − 負債・純資産の増加 = 換算差額になり、純資産に為替換算調整勘定を置かない型では、0 でない換算差額の正常な資料が作れないため | 連結 CF 作成基準 第三 一 2・第二 一・第三 二 (投資活動・財務活動は主要な取引ごとに総額表示。2026-11-04 に本文を取得して確認)・第四 1・第三 三 (研究 §2.3。文書にある)。取得した版の表題は「作成基準（案）」(§9)。短期借入金など回転の速い項目の純額表示は注解（案）(注８) による (S2)。合わせないと、会計の分かる遊び手に正常が異変に見える。IFRS では営業活動を当期利益から始めることも認められるので、基準の表示を出す (設計) |
| G5 | **正常な資料は、次の単純化に従う**: 有形固定資産の除却・売却・減損は無い、特別損失は現金で支払う項目に限る、繰延税金・還付税金は無い、資本金・資本剰余金は期中に変わらない (増資なし)、自己株式の取得はしない、固定資産は有形固定資産と投資その他の資産だけで、無形固定資産・のれんとその償却は置かない (CF の減価償却費は有形固定資産の分だけ。c04 のソフトウェアも置かない)、長期借入金は 1 年内返済予定への振替を置かず直接増減する (CF の長期借入れによる収入 − 返済による支出 = 長期借入金の増減)。**配当**: T1 の年間配当金・配当金総額・配当性向は、当期に基準日が属する配当 (中間 + 期末。作成要領 p.27) で、T4 の「配当金の支払額」は 前期の期末配当 + 当期の中間配当 (1 株当たり額 × 株式数。T1 の配当の状況の前期・当期の欄から検算できる) とする。両者は一般に一致しない。中間配当を置かない会社は T4 = 前期の期末配当。当期の利益剰余金の配当による減少は T4 の支払額に等しい。この単純化があるので、H-02・H-07・H-09 などの「連動」が一意の等式になる | 設計。現実の資料はもっと複雑だが、ゲームの正常は一意に検算できる必要がある (charter の失敗 1)。配当の関係は、作成要領 p.24 (配当支払開始予定日は期末配当の支払開始予定日) と p.27 (配当は当該事業年度に基準日が属するもの) による (文書にある)。T4 か T5 に、この単純化と矛盾する記載を出さない。試作 verify.py の「配当金総額 = T4 の支払額」の単純化とは違う (§9) |
| G6 | **1 つの資料束の異変は 0 個か 1 個**。異変の位置は (画面 ID, 項目名, 期) で記録し、答え合わせの画面が示せるようにする | requirements.md 受け入れ条件 4。設計 |
| G7 | **見た目の異変 (やさしい) は、会計の知識が無くても、読む・見比べる・四則演算で見つかる**。むずかしいは、会計の等式・定義・資料のあいだの照合が要る | 要件の難易度 (理解の表) |
| G8 | **紛らわしい正常を作らない**: 営業 + 投資 + 財務 ≠ 増減額に見える場合を作らない (換算差額の行は全社 0。G4)。現金及び預金 ≠ CF 期末残高に見える場合は資金の範囲の注記がある (正常は一致させる)。IR の金額が億円表記でも、短信の百万円との換算は正確に合わせる (c03・c05・c06・c08・c10)。億円は「百万円 ÷ 100 を小数第一位まで四捨五入」で書く (12,456 百万円 → 124.6 億円。5 百万円の端数は切り上げ)。桁数は会社の全資料で 1 つに統一する | 研究 §2.3 の「紛らわしい正常」の指摘 |

| G10 | **種類の ID (E-01・H-01 など) は、保存のキーとして使われる (experience.md の P5)**。実装が始まったあとは変えない。種類を足すときは新しい ID を付け、使わなくなった種類は欠番にして、ID を再利用しない。実装の前に技術の Sub-task (#52) の知らせで系統の名前と ID を合わせる変更は、この限りでない | experience.md §6.7 の `AnomalyKind.id`「保存のキー (変えない約束)」。設計 |
| G11 | **資料の科目名は全社で汎用**: 売掛金・棚卸資産・買掛金・有形固定資産・現金及び預金など。companies.md §5.2 の業種の名前 (c06 の完成工事未収入金・未成工事支出金、c08 の販売用不動産など) は、事業の性格を説明するためだけのもので、資料に出す科目名ではない。E-05・H-05・H-06・H-28 の科目も、この汎用の名前で書く | 型の項目キーごとに、標準の名前は 1 つ (docs/design.md §4.1 の `labels.ts`)。experience.md の「用語は全社で同じ」と合う。設計 |

## 4. 答え合わせの説明文の型

答え合わせの画面は、異変があった問題で「場所」と「内容」を示す (requirements.md 受け入れ条件 4)。内容の文は、次の型の空欄 `{…}` を、問題データの数字で埋めて作る (charter の「single source of truth」: 文面も問題データから作る)。各種類の例文の数字は説明用の仮の数字。

| 型 | 名前 | 文の骨組み |
| --- | --- | --- |
| K1 | 食い違い型 | `{画面 A}の{項目}は{値 A}ですが、{画面 B}の同じ項目は{値 B}です。{どちらが正しいか・なぜ同じになるはずか}。` |
| K2 | 計算型 | `{項目}は {式} = {計算値} になるはずですが、{画面}では{表示値}と書かれています。` |
| K3 | 等式型 | `{左辺の名前}({値})と{右辺の名前}({値})が一致しません (差 {差})。{なぜこの等式が成り立つかの 1 文}。` |
| K4 | 連動型 | `{画面 A}の{項目}の増減({値})は、{画面 B}の{項目}の{増減または額}({値})と一致するはずですが、一致しません。{なぜ連動するかの 1 文}。` |
| K5 | 記載型 | `{あるべき記載}が{無い／違う}。{根拠}では{こう書く}と定められています。` |
| K6 | 説明矛盾型 | `「{文章}」と書かれていますが、{数字}は{逆の動き}です。` |
| K7 | 体裁型 | `{体裁の決まり}に反しています ({具体})。同じ資料の他の箇所は{こう書かれている}。` |
| K8 | パターン型 | `{指標 1}・{指標 2}・{指標 3}が同時に{こう動いて}います。これは{一般に何が疑われるか}の典型的な形です。` |

- 答え合わせは、断定できることだけを書く。確度 C の種類 (K8) は「疑われる」と書き、「不正だ」とは書かない。
- 異変の無い問題の答え合わせは、「確かめた整合」を短く並べる文にする (画面の Task が決める。型は無い)。

## 6. 各異変の定義

各節の見出し (「画面と場所」「どう変わるか」「破れる規則」「適する会社」「答え合わせ」「正常の条件」「根拠」) は、`check_anomalies.py` が確かめる。破れる規則の名前は、試作の検証器 (docs/plans/spike/verify.py・check_ir.py) の規則 ID と同じ書き方で示す (製品の検証器の規則名は技術の Task が決める)。付随して落ちる規則は、試作の実測 (inject.py の 6 種類) と同じ考え方で導いたもので、試作に無い種類は未実測 (§9)。例文の数字は説明用の仮の数字。

## 7. 問題の数の見積もり (難易度ごとに 25 問以上)

`check_anomalies.py` が出す「独立な問題の数」は、種類ごとに (場所の数 × 適する会社の数) を足した値で、同じ (種類, 場所, 会社) は 1 つと数えた**下限**。期 (第 N 期・第 N+1 期。companies.md §5.1) を変えた資料束は数えていない。確度 C の種類 (H-25〜H-27) は数えていない。

| 難易度 | 種類 | 独立な問題の数 (確度 A・B) | 必要な数 | 判定 |
| --- | --- | --- | --- | --- |
| やさしい | 17 | 640 | 25 | 満たす |
| むずかしい | 25 (確度 A・B。C の 3 種類を除く) | 515 | 25 | 満たす |

- 難易度ごとに 25 問以上を作る目安 (正常と異変が半々なら、異変のある問題は 13 問ずつ): やさしいは 17 種類から 13 種類を 1 問ずつ、むずかしいは 25 種類から 13 種類を 1 問ずつ選べば、同じ種類が 2 度出ない。種類の重なりを避けられるので、8 社連続で同じ種類にほぼ出会わない (理解の表の「問題の数」の趣旨)。
- 場所と会社を変えれば、同じ種類でも別の問題になる (下限は上の表)。残りの 12 問ずつ (正常) は、会社 10 社 × 期で作る。正常の資料束の数は、会社の数 × 期の数が上限で、種類の数には依らない。
- 8 社連続の 1 回の挑戦で、同じ会社が 2 度出ない (companies.md §1: 会社 10 社 ≥ 8)。
