# 正常を覚えられるかの確かめ: 遊び手に渡す形

Task #137 / Sub-task #150。根拠: [plans.md](../plans/redesign/plans.md) §8.1 の Q16 の測り方・Q17 (人数)、[requirements.md](../requirements.md) の「正常を覚えられるかの確認」(作り始めに、カードの試作で、初めて遊ぶ人間が正常を覚えて異変に気づけるかを確かめる。集められる人数で。足りない分は未確認と記録する)。
印: **要件** / **文書** (出典つき) / **仮定** (plans.md §8.1 が仮定とした値。本書で確かめたものではない) / **未確認**。

**結果は、本書を作った時点では無い (未確認)**。人間の遊び手を集めて回すのは、人間か責任者の仕事 (AI の疑似ユーザーは目安から外す。**文書**: NN/g「Synthetic Users」2024-06-21。plans.md §8.1 が取得して確認した)。

## 1. 確かめたいこと (1 つの問い)

> 0 社目 (見本) を見たあと、**型からのずれ**を見つけ、**正常を異変と誤らない**か。

- 「型からのずれ」= 欄の欠落・欄の並びの入れ替え・単位の語の違い・同じ欄の重複 (台帳 E-19・E-20・E-03・E-22)。向きの逆・桁・比率の計算違いは、0 社目が無くても 1 枚の中で見つかるので使わない (**文書**: plans.md §8.1)。
- 効けば、「カードの形を毎周同じにして、正常を覚えさせる」設計 (要件) が成り立つ見込みになる。効かなければ、責任者が 1 回直し (0 社目に「正常」と「異変の例」を並べるなど)、それでも駄目なら人間に聞く (**文書**: plans.md Q16 の既定 1)。

## 2. 必要なもの

| もの | 中身 |
| --- | --- |
| 試作の URL | `<URL>` = 責任者が Vercel の一時的な公開で置いた `proto.html` の URL (本書は公開前に書いたので、ここは責任者が埋める)。ローカルなら `npm run dev:proto` の `http://localhost:5173/proto.html` |
| 遊び手 | **初めて遊ぶ人間 5 人** (**文書**: NN/g「How Many Test Users in a Usability Study?」2012-06-03。質的な確認は 5 人。**5 人は方向の確認で、統計的な結論ではない**)。集められる人数でよい (2 人以上。**要件**・Q17 の既定 1)。足りない分は「未確認」と記録する |
| 端末 | スマホ (縦) か PC。1 人は 1 台で通す。画面の幅は 320〜414 px のスマホが 1 人は入るとよい |
| 時間 | 1 人 約 15 分 (**仮定**: 1 周 = 8 枚 × 約 30 秒 ≈ 4 分 × 2 条件 + 説明・感想 約 7 分) |
| 係 | 進行 1 人 (人間か責任者が頼む人)。**ヒントを出さない** |

## 3. 条件と URL

1 人が 2 つの条件を、続けて遊ぶ。**条件 A (見本あり)** が合否の対象、**条件 B (見本なし・別の型)** は補助 (見本の効きを見る比較)。

| 条件 | 中身 | URL (`<P>` は参加者の記号。`<S>` は下の表の種) |
| --- | --- | --- |
| A 見本あり | 0 社目に、型 E1 (もうけ) の「記入例」を見せる → 8 枚 (異変 4 + 正常 4)。型はすべて E1 | `<URL>?mode=test&shape=E1&sample=on&pid=<P>&seed=<S>` |
| B 見本なし | 見本を見せず、型 E3 (持ち物。別の語・並び) の 8 枚 | `<URL>?mode=test&shape=E3&sample=off&pid=<P>&seed=<S>` |

- **順序は入れ替える** (学習の持ち越しを均す): 1・3・5 人目は A → B、2・4 人目は B → A。
- **種は人と条件ごとに変える** (同じ会社の並びを覚えさせない。同じ種は同じ 8 枚を出す):

| 参加者 | 記号 `<P>` | A の種 | B の種 | 順序 |
| --- | --- | --- | --- | --- |
| 1 人目 | P1 | 1011 | 1012 | A → B |
| 2 人目 | P2 | 1021 | 1022 | B → A |
| 3 人目 | P3 | 1031 | 1032 | A → B |
| 4 人目 | P4 | 1041 | 1042 | B → A |
| 5 人目 | P5 | 1051 | 1052 | A → B |

- A と B で型が違うのは、同じ人が同じ型を 2 回見ると、2 回目に型を覚えてしまうため。**そのぶん、A と B の差には型の違いが混ざる** (交絡)。補助の読み方は §6。

## 4. 進行の台本 (進行が読む)

1. (1 分) 「架空の会社の決算の伝票が、1 枚ずつ出ます。**いつも通り**か**異変あり**かを、1 回だけ押してください。急がなくて構いません。」 — **何が異変かは言わない。** 画面の言葉以外のヒントを出さない。
2. 遊び手に URL を開いてもらう (A か B。表の順序)。画面の案内に従って 8 枚を通す。**間違えても 0 社目には戻らない** (確かめでは、8 枚の答えを全部記録する。遊びの本体とは違う)。
3. 8 枚が終わると「記録」が出る。**「記録をコピー」を押してもらい、進行に渡す** (貼ってもらうか、画面を見せてもらう)。
4. もう 1 つの条件を同じように遊んでもらう。
5. (約 3 分) 感想を聞く。答えは書き取る (記録票の「感想」の欄):
   - どこで「おかしい」と気づいたか。
   - いつも通りの見本を見たことは、役に立ったか (A の人に)。
   - 迷った伝票はあったか。
6. 記録票 (§7) を埋める。

- 遊びの途中で、**画面の押し方や用語の質問には答えてよい** (確かめたいのは、見つけられるかで、操作ではない)。**答え (どの伝票が異変か) は言わない**。
- 画面は、押すたびに答え合わせ (正解・不正解と、異変の場所) を見せる。これは遊びの本体と同じ。**答え合わせで学ぶ分が、見つけ率に混ざる** (限界。§8)。

## 5. 判定の基準 (**仮定**: plans.md §8.1)

- 1 人の合格 (条件 A): **異変 4 枚中 3 枚以上を見つけ、かつ、正常 4 枚中の誤り (正常を異変と答えた) が 1 枚以下**。
- 当て推量 (どの枚も 50%) で 1 人が合格する確率は約 9.8%、5 人中 4 人以上が合格する確率は約 0.04% (**導いた**: 二項分布。1 人 = (5/16) × (5/16)。`src/proto/playtest.ts` の `guessProbability`・テスト P7 で再現できる)。

| 人数と合格 | 読み方 |
| --- | --- |
| 5 人以上で全員 | **強い合図** (正常を覚えられる見込みが高い) |
| 5 人以上で 1 人だけ不合格 (4/5) | **弱い合図**。次の扱い (§9) に進む前に、感想を見る |
| 5 人以上で 4 人未満 | **効かない** → §9 |
| 5 人に満たない | 全員合格なら「弱い合図」、それ以外は「未確認」 (Q17) |

## 6. 補助 (見本の効き): 条件 B との比較

- 同じ人の「見つけ数」の差 (A − B) を見る。A が B より多ければ、見本が効いた合図。
- **両方の条件で 4/4 (天井) のときの同率は、「効かない」に数えない** (正常を覚えなくても、4 行のカードでは目立つ型のずれは見つかる。**文書**: plans.md §8.1)。集計は「天井」と添える。
- 被験者内の比較は、被験者間より人数が少なくて済む (Bellemare ほか IZA DP 8583, 2014。ただし贈与交換の実験の話で、**5 人の方向の確認にはそのままは当てはまらない**)。A と B は型が違うので、差は**参考**で、結論には使わない。

## 7. 記録と集計

- 画面の「記録」の文 (参加者・条件・種・見つけ・誤り・各枚の正解と答えと所要秒) を、人ごとに保存する。
- **集計**: `<URL>?mode=summary` を開き、5 人ぶんの「記録をコピー」の文を続けて貼って「集計する」を押すと、判定と表が出る (中身は `src/proto/playtest.ts` の `aggregate`。テスト P8〜P11)。

| --- | --- | --- | --- | --- | --- |
| P1 | A → B | | | | |
| P2 | B → A | | | | |
| P3 | A → B | | | | |
| P4 | B → A | | | | |
| P5 | A → B | | | | |

## 8. 限界 (**未確認**を含む)

- 5 人は方向の確認。**統計的な結論ではない**。人が集まらなければ、集められた人数で回し、足りない分は「未確認」と記録する (要件)。
- 答え合わせを毎枚見せるので、**学習が見つけ率に混ざる**。「0 社目だけで覚えたか」は分けられない (A の最初の 2〜3 枚の見つけ方を、感想で補う)。
- A と B の型が違う (E1 / E3)。差の読み方は §6。
- やさしいの 3 形のうち、確かめるのは E1 と E3 だけ。E2 (棒グラフ) は確かめていない。
- 異変が単調にならないか (数周で同じ異変に当たらないか) は、この確かめでは測らない。遊びの本体で、`?seed=N` を替えて数周遊び、感想で見る (**未確認**)。

## 9. 効かなかったとき (plans.md Q16 の既定 1)

1. 責任者が工夫を 1 回だけ足して、もう一度確かめる。例: 0 社目に「正常」と「異変の例」を並べて見せる・見分けのヒントを、紙の上の短い掲示に足す・異変の種類を増やす (設計 v2 §2)。
2. それでも駄目なら、**A2 (形を問題ごとに変える)・B (資料を開く)・D (同じ会社の 8 期)・A のまま続ける** のどれにするかを、人間に聞く。**自動で D に切り替えない** (D は「8社」を変えるので、人間の承認が要る。**文書**: plans.md Q16)。
