## 1. 形の仕様 (#175)

### 1.1 言葉 (GLOSSARY.md を直した)

| 語 | v3 での意味 |
| --- | --- |
| カード | 1 回の判定で遊び手が見る、決算の要約 1 枚。やさしいも、むずかしいも、同じ作りの 1 枚 (§1.2) |
| 資料 | むずかしいだけが、カードの下に足して見せる、決算短信のまとめと IR のひとこと (§1.3)。第 1 版の「資料束」とは別 (資料束は 10 画面の束) |

| 欄 (スロット) | 形の 1 つの部品。**数字**欄 (科目名 + 数値 1 つ + 単位)・**文**欄 (1 行の文)・**見出し語**・**表題** |
| 表題 | カードの一番上の行。社章・社名・期・期末日。全社で同じ位置 |

数え方 (**設計**。要件 7 の「数字 4 つまで」を数えられる形にする。v2 §1.1 を引き継ぐ):
- 数字の数 = 形に載る**数値のセルの数**。棒グラフの棒 1 本も数字 1 つに数える (v3 のやさしいは棒を使わない。§1.2)。比率 (営業利益率) も数字 1 つ。
- 文の数 = 文欄の数。文欄は **1 文・40 字以内** (v2 §1.1。出典 Xbox Accessibility Guideline 101「Line width ≤ 80 characters (40 for CJK)」。2026-11-05 に本文を取得して確認した記録が v2 にある)。`deriveCards` が作る文欄の文字列は、検証器が 40 字以内を**異変の問題を含む全問**に当てる (異変の問題の文だけが長いと、行の数で答えが分かる)。
- **枠の外** (数えない): 表題 (社章・社名・期・期末日)、見出し語 (【増益】など 1 語)、欄の科目名と単位の語。
- **上限は正常なカードに当てる**。異変のカードは、欄の欠落で 1 つ減り、**欄の重複 (E-22) で 1 つ増える**ので、数字が 5 つ載る異変のカードがありうる (**設計**。「正常は 1 つ」と、重複を異変に残す人間の言葉 (第 3 版) を両立させる読み方。要件 7 の文言との関係は §3.4 の未確認に書く)。

### 1.2 やさしいの形 (1 種類。名前: もうけ)

**要件**: カード 1 枚。要素は 8 番出口の通路のように数種類で、詰め込みすぎない。毎回まったく同じ並び・同じ見た目で、変わるのは会社と数字だけ (第 3 版)。

**8 番出口の通路の考えを、こう写す** (**設計**): 通路が毎回同じで、壁のポスター・扉・案内板・天井の灯りなど**数種類のものだけが並び、そのどれかが変わる**。カードも同じで、**要素の種類は 4 つ** (表題・見出し語・数字の欄・欄の科目名と単位) だけ。毎回同じ順に並び、遊び手は「いつもの並び」を覚える。異変は、その要素のどれかが「いつもと違う」こと。

| 並び | 要素 | 欄の key | 見せるもの | セル (正本。`deriveCards` が使う) |
| --- | --- | --- | --- | --- |
| 0 | 表題 | `frame` | 社章・社名・期 (2024年3月期)・期末日 (2024年3月31日) | 社章・社名 = `companies.json`。期 = `tanshin.header.periodLabel`。期末日 = `tanshin.columnDates.incomeStatement.current` |
| 1 | 見出し語 | `headline` | 【増益】または【減益】+ 見て分かる言い換え (もうけが増えた/減った) | `ir.statements` の営業利益の主張 (`claims` の `metric = operatingIncome` と `direction`。v2 R-D5) |
| 2 | 数字 ① | `sales` | 売上高 (百万円) | `tanshin.incomeStatement.current.netSales` |
| 3 | 数字 ② | `opPrev` | 営業利益 (前期) (百万円) | `tanshin.incomeStatement.previous.operatingIncome` |
| 4 | 数字 ③ | `opCurr` | 営業利益 (当期) (百万円) | `tanshin.incomeStatement.current.operatingIncome` |
| 5 | 数字 ④ | `margin` | 営業利益率 (%) | `tanshin.summary.operatingMargin` |

- 数字の欄 = 科目名 + 数字 (桁区切りのカンマ付き) + 単位の語 + 見て分かる言い換え。**言い換えは科目名の項目キー (`itemKey`) ごとに `labels.ts` の 1 か所**で持ち、科目名の差し替え (`labelOverrides`) の影響を受けない (v2 の #136 包括レビュー 1 回目 N2)。
- 例 (easy-017 の数字。実在しない架空の会社): 【増益】 売上高 96,930 / 営業利益 前期 4,480・当期 4,920 / 営業利益率 5.1%。(**測った**: `src/data/problems/easy/easy-017.json`)
- 数字は 4 つ (上限の内)。文欄は無い (見出し語だけ。v2 §1.1 の「やさしいは文欄を持たない」を引き継ぐ)。
- **形の中で、正常のとき必ず成り立つ関係** (遊び手が 1 回で確かめられるもの。台帳 §2 が異変の種類と結ぶ。**設計**):
  1. 見出し語の向き = 営業利益の前期 → 当期の向き (増益なら ② < ③)
  2. 営業利益率 = ③ ÷ ① × 100 (規則 `ratio-operating-margin` が読む 3 つのセルがすべて載る。出典: JPX 作成要領 p.26「売上高営業利益率 = 営業利益 ÷ 売上高 × 100」(v2 §2.2 の E-12 に原文確認の記録がある))
  3. ② と ③ は同じ桁帯 (前期と当期の営業利益が 10 倍違うことは正常ではない)。③ は ① より小さい (営業利益は売上高の一部)
  4. 表題の期と期末日が合う (「2024年3月期」の期末日は 2024 年 3 月の末日)
- **正常な 12 問で、これらが成り立つこと** (**測った**。再現: `node --experimental-strip-types --no-warnings docs/plans/redesign/spike-design/v3-inject-easy.ts` の (1) の行): 形に載るセルだけで落ちる検証器の違反 0 件。営業利益率と ③ ÷ ① × 100 の差は最大 0.039 ポイント (1 の位が 0.1 の丸めの内)。減益の問題 2 問・増益 10 問。前期比の変化の最小 2.1% (向きが読み取れる)。負の数を持つ問題 0 (E-25 の符号の異変が、正常の△とまぎれない)。
- 見本 (0 社目): 毎周の最初に、見本の問題 (正常。出題のプールに入れない `sample.json`) から `deriveCards` で作った**この 1 枚**を見せる。見本が 1 つなので「正常はこれ」が 1 つに決まる (第 3 版)。

**採らなかった要素と、その理由** (**導いた**: 台帳 §2.2 の数え方で、種類の数を比べた):

| 案 | 内容 | 種類の数 (§2.1 の数え方) | 採らない理由 |
| --- | --- | --- | --- |
| **A (採用)** | 見出し語 + 売上高・営業利益 (前期・当期)・営業利益率 | **12** (§2.2) | — |
| B 棒入り | 見出し語 + 売上高 (前期・当期) + 棒 2 本 (v2 の E2 型) | 11 (向きの逆・桁・棒・単位・綴り・欠落・カンマ・重複・符号・見出し語の種類・期末日) | 棒 2 本が数字 2 つに数えられ (v2 の数え方)、割合 (E-12)・売上高と営業利益の大小 (E-24) の 2 種類が外れる。棒の 2 種類 (E-06・E-07) は §2.1 で 1 種類にまとまる |
| C ひとこと入り | A に文欄 1 つ (例: 「営業利益は前期より増えた」) | 12 (A と同じ。文は見出し語と同じ主張から作るので手がかりが増えない) | 文を読ませる分だけ重くなる。見出し語が言い換え付きの「ひとこと」を兼ねる |

### 1.3 むずかしいの形 (1 種類。名前: もうけ + 資料)

**要件**: カードに、決算短信の要約などの資料を足して見せる。資料の並び・見た目は毎回同じ (第 3 版)。むずかしいは「会計の関係と、決算短信と IR のあいだの食い違いを多めに」(第 2 版)。

並び (上から下。**設計**): **カード** (§1.2 とまったく同じ。言い換えは添えない) → **資料 1: 決算短信のまとめ** → **資料 2: IR のひとこと**。カードは、やさしいで覚えた形がそのまま出るので、むずかしいでも「いつものカード」が基準になる。

| 部 | 要素 | 欄の key | 見せるもの | セル |

| 資料 1 損益 | 数字 | `pbt` | 税金等調整前当期純利益 (当期) | `tanshin.incomeStatement.current.incomeBeforeTax` |

### 1.4 カードを問題データから導く規則 (v2 §1.2 の引き継ぎと変更)

charter の原則「single source of truth」: **カードと資料は問題データ 1 か所から導く。専用のデータは持たない。** v2 の規則の v3 での扱い:

| 規則 (v2 §1.2) | v3 | 変わる所 |
| --- | --- | --- |
| R-D1 純関数 `deriveCards(problem, company, difficulty)` | **引き継ぐ**。引数が `shape` から `difficulty` に変わる (形は難易度で 1 つに決まる) | `ShapeId`・形の選択が不要 |
| R-D2 異変は問題データの変更で表す (カードを手で書き換えない) | **引き継ぐ**。`cardEdits` の op は `drop`・`format`・`unit`・`dup` と、見出し語の `headline` (§1.6)。**`swap` は無い** (並びの入れ替えは異変にしない) | `swap` の削除 |
| R-D3 答え合わせの場所の当て方 (`places` を `Slot.reads` に当てる) | **引き継ぐ**。表題の期・期末日の欄 `frame.period` (`reads` = 期と期末日。#173 の N2 の直しを取り込む) を足す | `frame.period` |
| R-D4 正常の整合 (異変の無い問題は検証器の全規則を満たす) | **引き継ぐ**。やさしい 12 問・むずかしい 16 問の正常で成り立つことを §3.3 で測った | — |
| R-D5 見出し語・IR の文を claims から型で作る | **引き継ぐ**。やさしい・むずかしいのカードの見出し語は営業利益の主張だけ (増益/減益)。むずかしいの資料 2 の文 `irOcf` は営業 CF の主張。売上高の主張は使わない (カードに前期の売上高が無く、向きを読めない)。**1 問の中で営業利益・営業 CF の主張はちょうど 1 つ**を全問に当てる (v2 の `claims-count` を、売上高の主張を除いて) | 売上高の主張を外す |
| R-D6 (#173 で足した) `card-unit` = 金額の欄ごとに、その資料の単位の語 (短信 = 百万円、IR = `irUnit`) | **取り込む** (§2.5 の H-29) | — |

### 1.5 形の出方の規則 (v2 §1.5 R-S1〜S6 を 1 種類に合わせて直す・外す)

v2 は、形が 3 種類あるために「形の出方で答えが漏れる」ことを塞ぐ規則 (R-S1〜S6) を持っていた。**形が 1 種類なら、形の出方そのものが無い**ので、その分は外れる。会社・期・向きの語から答えが漏れることを塞ぐ分は残る。

| 規則 | v2 の内容 | v3 |
| --- | --- | --- |
| R-S1 形は問題から決めない (枠ごとに一様に引く) | 形を異変の有無と別の乱数の流れで引く | **外す** (形が 1 つ) |
| R-S2 次に異変の有無を引く (`ANOMALY_RATIO` = 0.5) | 今のまま | **引き継ぐ** |
| R-S3 その形で出せる問題だけが候補 | 形ごとの候補 (正常 = 全部、異変 = その形で見えるもの) | **候補 = 正常な問題は全部・異変の問題は全部** (全問が 1 つの形の上で見えることは、データの検査 V1・V2 が問題ごとに保証する。出題で形を見ない) |
| R-S4 見える条件 V1・V2 | `places` が形のカードに載る・主な規則の違反の `paths` が形のカードに載る | **引き継ぐ** (「形」を 1 つに決めて、問題ごとに検査する。出題には使わない) |
| R-S5 (a) 形ごとに 8 社以上・(b) 全 10 社が形ごとに異変と正常の両方 | 形ごとの出題の確実さ | **難易度ごとに言い換える**: (b) 全 10 社が、異変の問題と正常な問題の**両方**を持つ (会社から答えが漏れない)。(a) は (b) に含まれる (10 社 ≥ 8 社) |
| R-S5 (c) 1 形が見せる種類 4 つ以上 | 形ごとの種類の下限 | **外す**。難易度の種類は 12 以上 (要件。台帳 §2) で、形が 1 つなのでこれが形の種類になる |
| R-S5 (d) 会社 × 期から答えが漏れない | どの (会社, 期) にも正常と異変の両方 | **引き継ぐ** (異変の問題は同じ (会社, 期) の正常な問題から異変 1 つを加えて作る。再計算しない種類の例外も v2 §1.5 のまま) |
| R-S5 (e) プールの `anomaly-ratio` を外す | 割合は `draw` の抽選が決める | **引き継ぐ** |
| R-S5 (f) claims から作る語は正常にも両方の向きが出る | やさしい = 減収 3 社・減益 3 社、むずかしい = 減収 3 社・営業 CF マイナス 1 社 | **やさしい = 減益 3 社以上** (見出し語は営業利益の主張だけなので、減収は要らない)、**むずかしい = 減益 3 社以上・営業 CF がマイナスの会社 1 社以上** (カードの【減益】と資料 2 の文の「マイナス」) |
| R-S6 出題の確かめ (1 万周で形の出現率が 1/3 ± 1.5 ポイント) | 形の偏りの確かめ | **形の出現率は外す**。残すのは、同じ 1 万周 (8 万枠) での**異変の枠の割合が 0.5 ± 1.5 ポイント** (標準誤差 √(0.5 × 0.5 ÷ 80,000) = 0.18 ポイント。**導いた**)。足すのは、**難易度のどの種類も 1 万周で出る**こと (形の出方が無くなった代わりに、種類の出方を見る) |

- **問題の数** (**導いた**): 1 つの (会社, 期) に、正常 1 問と、異変の問題を**種類ごとに 1 問**ずつ (異変の問題は同じ (会社, 期) の正常な問題から作る。R-S5 (d))。10 社 × 1 期なら、種類 12 で 10 × (1 + 12) = **130 問**、すべての (会社, 期) に全種類を作る必要は無く、要件の「25 問以上」は、**種類ごとに 2 問以上・2 社以上**を最小にすれば 12 × 2 + 10 = 34 問で満たす (**設計**。種類ごとに 2 社以上: 数周で同じ会社の同じ異変だけを覚えられないため)。問題の数の決めはデータの Task (#139・#140)。

### 1.6 形のずれの異変を表す `cardEdits` (v2 §1.6 の縮小)

数字・文のセルを変える異変は、今の問題データだけで表せる。**欄の形のずれ** (欄の欠落・数字の書式・単位の語・欄の重複) は、問題データに `cardEdits` を足して表す (**設計**。型の細部はデータの Task が決める。ここは仕様)。

```ts
type CardEdit =
  | { card: 0; slot: string; op: 'drop' }                                              // 欄の欠落
  | { card: 0; slot: string; op: 'format'; style: 'no-comma' | 'comma-shift' }           // 数字のカンマの位置
  | { card: 0; slot: string; op: 'unit'; unit: string }                                 // 欄の単位の語
  | { card: 0; slot: string; op: 'dup' }                                                // 欄の重複 (同じ欄が 2 回出る)
  | { card: 0; op: 'headline'; word: string };                                          // 見出し語を別の型の語にする (増益のカードに【増収】)
```

- **`swap` (欄の並びの入れ替え) は無い** (第 3 版: 並びが入れ替わっただけで中身は正しいものは、異変に入れない)。v2 の `CardEdit` から削除する。
- 形が 1 つなので、v2 の `shape` は要らない。`card` は、やさしいは常に 0。むずかしいは、カードと資料を 1 つの欄の並びとして持ち、`slot` の key (§1.2・§1.3 の表) で指す。
- **op ごとに当ててよい欄** (v2 §1.6 の「表示が実際に変わる組だけ」を、1 つの形に合わせる。**測った**: `v3-inject-easy.ts` の (3) の行。やさしいの正常 12 問):
  - `unit`: 金額の欄だけ (比率・文欄には当てない)。語は、その欄の正常の語以外 (§2.5)。
  - `format` の `no-comma`: 金額の欄で、整数部が 4 桁以上のもの。やさしいの正常 12 問では、① 売上高 12/12・② 営業利益 (前期) 10/12・③ 営業利益 (当期) 10/12。`comma-shift` は整数部 5 桁以上: ① 売上高 11/12・②・③ は 0/12 (営業利益が 5 桁になる正常な問題が無い)。**やさしいで `comma-shift` を当てられるのは ① 売上高だけ**。% の欄には当てない。
  - `dup`: 数字の欄・見出し語・文欄のどれでもよい (同じ欄がもう 1 つ増えれば必ず見た目が変わる)。数字の欄の重複は、数字が 5 つ載る (§1.1)。
  - `drop`: どの欄でもよい (欄が消えれば必ず変わる)。表題・見出し語を消す異変は作らない (欠けると「何のカードか」が消え、見出し語の欠落は E-23 の語の違いと見え方が重なる)。
  - `headline`: 元の語の組の外の語だけ (増益・減益 → 増収・減収)。
- 検証器は、編集で表示が実際に変わることを確かめる (v2 §2.8 の検査 5。引き継ぐ)。1 つの異変は 1 つの編集 (台帳 §2 の G6: 異変は 0 個か 1 個)。
