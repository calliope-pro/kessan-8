### 1.3 むずかしいの形 (1 種類。名前: もうけ + 資料)

**要件**: カードに、決算短信の要約などの資料を足して見せる。資料の並び・見た目は毎回同じ (第 3 版)。むずかしいは「会計の関係と、決算短信と IR のあいだの食い違いを多めに」(第 2 版)。

**要件の読み方 (責任者の決定 2026-11-08 (問 2 = (A)))**: 第 2 版の理解の表「1 回の判定」の行は「やさしいは 1 枚 (数字 4 つまで)、むずかしいは決算短信と IR の 2 枚 (各 数字 4 つ + 文 3 つまで)」。第 3 版の「むずかしいの見せ方」は「カードに、決算短信の要約などの資料を足して見せる」で、人間は「柔軟にやれよ」と答えた。**責任者が (A) と決めた**: むずかしいは経理・投資に詳しい人向けで、資料を足すのは人間の指示なので、この上限は外れる。資料の量は設計で決める (下)。ただし**「びっしりで読めない」は避ける** (次の「組み方」)。読み方 B (各資料に上限を残す) は採らない。

**組み方 (設計。責任者の決定: 実物の形に寄せつつ、余白と区切りで目が走る組み方にする)**:
- 資料 1 は決算短信のサマリーの順 (経営成績 → 財政状態 → キャッシュ・フロー → 注記。JPX 作成要領 2026 年 7 月版の様式 p.22〜23 の並び。**様式の本文を PDFKit で文字にして確かめた。2026-11-08**) に並べる。資料 2 (IR) は、短信と同じ順の「ひとこと」。
- **ブロックは 5 つ** (資料 1 = 損益・貸借・キャッシュ・フロー・注記、資料 2 = IR のひとこと)。ブロックごとに見出し行と区切りの罫を置き、ブロックの間に余白を取る。1 ブロックの数字は 5 つ以内、文は 1 行 1 欄。

### 1.6 形のずれの異変を表す `cardEdits` (v2 §1.6 の縮小)

数字・文のセルを変える異変は、今の問題データだけで表せる。**欄の形のずれ** (欄の欠落・数字の書式・単位の語・欄の重複) は、問題データに `cardEdits` を足して表す (**設計**。型の細部はデータの Task が決める。ここは仕様)。

```ts
type CardEdit =
  | { card: 0; slot: string; op: 'drop' }                                              // 欄の欠落
  | { card: 0; slot: string; op: 'format'; style: 'no-comma' | 'comma-shift' }           // 数字のカンマの位置
  | { card: 0; slot: string; op: 'unit'; unit: string }                                 // 欄の単位の語
  | { card: 0; slot: string; op: 'dup' }                                                // 欄の重複 (同じ欄が 2 回出る)
  | { card: 0; slot: string; op: 'suffix'; word: '前期' | '当期' }                        // 添え字の取り違え (「営業利益 (前期)」の添え字を「当期」にする。E-26)
  | { card: 0; slot: string; op: 'glyph'; at: number }                                    // 数字の中の 1 字を「X」にする (4,920 → 4,9X0。E-27)
  | { card: 0; slot: string; op: 'sign' }                                                // 金額の欄の表示に負の記号 △ を付ける (E-25・H-34。値は正のまま)
  | { card: 0; slot: 'period'; op: 'day'; day: 32 }                                         // 足元の期末日の表示の日を 32 にする (E-28。データのセルは変えない)
  | { card: 0; op: 'headline'; word: string };                                          // 見出し語を別の型の語にする (増益のカードに【増収】)
```

- **`swap` (欄の並びの入れ替え) は無い** (第 3 版: 並びが入れ替わっただけで中身は正しいものは、異変に入れない)。v2 の `CardEdit` から削除する。
- 形が 1 つなので、v2 の `shape` は要らない。`card` は、やさしいは常に 0。むずかしいは、カードと資料を 1 つの欄の並びとして持ち、`slot` の key (§1.2・§1.3 の表) で指す。
- **op ごとに当ててよい欄** (v2 §1.6 の「表示が実際に変わる組だけ」を、1 つの形に合わせる。**測った**: `v3-inject-easy.ts` の (3) の行。やさしいの正常 12 問):
  - `unit`: 金額の欄だけ (比率・文欄には当てない)。語は、その欄の正常の語以外 (§2.5)。
  - `format` の `no-comma`: 金額の欄で、整数部が 4 桁以上のもの。やさしいの正常 12 問では、① 売上高 12/12・② 営業利益 (前期) 10/12・③ 営業利益 (当期) 10/12。`comma-shift` は整数部 5 桁以上: ① 売上高 11/12・②・③ は 0/12 (営業利益が 5 桁になる正常な問題が無い)。**やさしいで `comma-shift` を当てられるのは ① 売上高だけ**。% の欄には当てない。

  - `suffix` (新規): 添え字を持つ欄 (`opPrev`・`opCurr`) だけ。添え字を、もう一方の語にする (「営業利益 (前期)」が 2 行並ぶ)。必ず見た目が変わる。

  - `sign` (新規): 値が正の金額の欄 (値 > 0) だけ。**表示だけ**に負の記号 △ を付け (96,930 → △96,930)、問題データのセルは正のまま・`changed` は空 (E-26〜E-28 と同じ)。E-25 = ① `sales` だけ、H-34 = §2.3 の H-34 の対象 11 欄。**値を負にして作らない**: 売上高を負にすると営業利益率 (正のまま) との食い違い (`ratio-operating-margin`) と ③ < ① の違反 (`card-relation`) が 12/12 で同時に出る。H-34 も、対象 11 欄のすべてが別の規則 (`bs-balance`・`link-cf-*`・`xdoc-*`・`ir-supp-net-debt` ほか) を同時に落とす。表示だけなら、データが基の正常と同じなので 0/12・0/16 (**測った**: `v3-inject-easy.ts` の (6)・`v3-inject-hard.ts` の H-34。#174 包括レビュー B2)。**今の `signOverrides` は使わない**: これは「負の数のセルの記号を差し替える」もの (`src/verifier/anomaly.ts` の検査 A22 が、負の数のセルを指さないと落とす) で、正の数に △ を付けられず、問題データ側の差し替えになる。v3 の異変では使わない (残すか外すかは #138)。
  - `day` (新規): 足元 `period` だけ。表示の日を 32 にする (どの月にも無い日)。問題データの `columnDates` は正しい日付のままなので、`deriveCards`・画面は期末日を **Date で整形せず、文字列の切り出しで作る** (Date で整形すると、2024-03-32 は Invalid Date になるか、繰り上がって 4 月 1 日になり、E-28 でなく E-04 の見え方になる。#138・#141 の申し送り。§3.2)。
  - `drop`: どの欄でもよい (欄が消えれば必ず変わる)。表題・見出し語を消す異変は作らない (欠けると「何のカードか」が消え、見出し語の欠落は E-23 の語の違いと見え方が重なる)。
  - `headline`: 元の語の組の外の語だけ (増益・減益 → 増収・減収)。
- 検証器は、編集で表示が実際に変わることを確かめる (v2 §2.8 の検査 5。引き継ぐ)。1 つの異変は 1 つの編集 (台帳 §2 の G6: 異変は 0 個か 1 個)。
