## 0. 結論

1. **画面は 7 つ**: タイトル (難易度の選択を同じ画面に置く)・0 社目 (見本)・n 社目 (カード + 札)・答え合わせ (正解)・差し戻し (不正解。1 秒で 0 社目へ自動で戻る)・クリア (完了票)・記録。(要件の「タイトル・難易度」は、1 つの画面に合成した。)流れは design-v2 §3.1 のまま、**v3 で足したのは 3 つ**: ① タイトルと難易度を 1 画面にして、始めるまでを 1 タップにする、② 札の言葉と押印の字を「いつも通り / 異変あり」にそろえ、「印」「確認印を押す」を画面から消す (人間の「印ってなんやねん」)、③ 進み具合を点検欄に加えて「あと N 社」の語でも言う。そのほか、④ 状態の抜け (初回・保存できない・準備中・途中で難易度を変える道) を埋めた (§2)。
2. **遊びの手触りは、案 B「押して確かめる (仕訳伝票の押印) を土台に、あと N 社の語と、クリアの完了票を足す」**を選んだ。3 案を遊び手の目で比べた (§3)。
3. **離脱しやすい瞬間を 9 つ洗い出し**、それぞれに対策と、確かめ方 (E2E か人の確かめ) を付けた (§4)。人でしか確かめられないものは、未確認として #186・#187 に渡す。
4. 遊び手に見える言葉の表 (§5)。**「印」「バグ」「エラー」「採点」「検算」「閲覧票」は画面に出さない**。
5. **PRODUCT.md・DESIGN.md を v3 に直した** (§7)。仕訳伝票の世界・朱 1 色・押印 1 回の動きは、責任者が決めた方向 (DESIGN.md の冒頭) のまま変えていない。

## 2. 画面と遷移

```
 タイトル(難易度) ──やさしい/むずかしい──▶ 0 社目 (見本) ──1 社目へ──▶ n 社目 (1〜8)
   │  ▲                                        ▲                          │ 札を 1 回
   │  └──────────戻る──────────┐              │                          ▼
   ▼                            │              │               答え合わせ ─ 正解 ─▶ 次の社 / 8 社目ならクリア
  記録 ─────────────戻る────────┘              │                  └─ 不正解 ─▶ 差し戻し (約 1 秒)
                                                └──────────── 自動で 0 社目へ ◀──────┘
 クリア ──もう一度──▶ 0 社目 (同じ難易度・新しい出題)    クリア ──別の難易度──▶ タイトル
```

| 画面 | 目的 | 見せるもの | 操作 (1 画面 1 操作) |
| --- | --- | --- | --- |
| **タイトル** | 1 タップで始める | 題名「８期連続」と、掲示 1 行 (例「決算の“いつも通り”を覚えて、異変を見つけよう」)。**やさしい・むずかしいの 2 つの大きなボタン** (それぞれ 1 行の説明。遊んだことがあれば「最高 N 社目」、**初めてなら何も出さない**)。下に小さく「記録」 | 難易度のボタン (押すと 0 社目へ)。記録。**出題できない難易度 (`canDraw` が false。問題データ v3 を作り直しているあいだ) は、ボタンを押せなくして「準備中」と出す** (`src/domain/draw.ts` の注記のとおり)。両方が準備中なら、掲示を「準備中です」にする |
| **0 社目 (見本)** | 毎周の最初に、正常を見せる | 「記入例」の朱印つきの正常なカード 1 枚 (むずかしいはカード + 資料)。掲示 **1 行**「これがいつも通り。ここからずれたら異変です」。**不正解で戻ったときは、掲示の位置に「さっきの異変: …」の文 (1〜3 行) を出し、さっきのカードは出さない** (design-v2 §3.1 のとおり。場所の強調は差し戻しの 1 秒で見せる。要件 受け入れ条件 4) | 「1 社目へ」(下端に固定。資料が長いむずかしいでも押せる)。小さな「難易度を変える」(上端。`TO_TITLE` を送り、合成したタイトルの画面に戻る) |
| **n 社目** | 見て、1 回で判定する | 上端に点検欄 8 つと「n 社目 / あと N 社」。中央にカード (むずかしいはカード + 資料を縦に流す)。下端に札 2 つ | 札「いつも通り」「異変あり」を **1 回** (取り消し・確認の窓は無い) |
| **答え合わせ (正解)** | 納得して次へ | カードに、押した札と同じ言葉の押印が落ちる。異変があった問題は、異変の場所を朱で囲み、内容の文を下端に出す。異変が無かった問題は「異変はありませんでした」 | 「次へ」(8 社目は「完了票へ」) |
| **差し戻し (不正解)** | 痛みを短くして、すぐ戻す | 「不正解」。カードが差し戻される (約 1 秒。動きを減らす設定では色の変化だけ)。異変の場所だけを強調。内容の文はここでは出さず、0 社目の「さっきの異変」で出す | 無し (自動で 0 社目へ)。「すぐ 0 社目へ」で飛ばせる |
| **クリア** | 達成を見せる | 完了票: 8 社の社章・社名。「見つけた異変 n / N」(**N = その難易度の出題のプールに出る異変の種類の数** (問題の `anomaly.kind` の重複なしの数。データ v3 が揃えば、やさしい 15・むずかしい 20 行になる。`anomaly-kinds.json` の件数 (v2 の使わない種類を含む) では数えない)・**n = `records.kinds` のうち、その種類の中にあるものの数** (前の版で遊んだ人の記録に残る v2 の種類は数えない。n が N を超えない)。記録の画面と同じ数)。この周で**新しく**見つけた種類があれば「今回 + k」(k = この周の前後の `kinds` の差) | 「もう一度」(同じ難易度)。「別の難易度」(= `TO_DIFFICULTY`。下) |
| **記録** | 続ける理由を持たせる | 難易度ごとに、最高の到達 (点検欄の塗りで見せる)・クリア回数・**見つけた異変の種類 n / N** (n・N はクリアの完了票と同じ。見つけた種類の名前は出し、まだの種類は「？」。種類の名前は答えを漏らさない)。**まだ遊んでいないとき**は、数の代わりに「まだ遊んでいません。8 社連続で正解するとクリアです」。**保存できないとき** (プライベートモードなどで localStorage が使えない。`src/domain/storage.ts` は例外を出さず、書けないだけ) は、遊べて、記録はこのページを開いている間だけで、「この端末では記録を保存できません」と 1 行出す | 戻る |

- **0 社目の大きさ** (**測った**。2026-11-09、試作 v3 を `?seed=21` で、最初の 0 社目と、1 社目で間違えたあとの 0 社目を測った。足元の下端 / 札の帯の上端): やさしい・最初の 0 社目は、375×667 で 581 / 597 (16 px の余裕で収まる)・**320×640 では 575 / 570 (5 px はみ出して、足元が札の帯に少し隠れる)**。ページの高さは 691〜697 px で、画面より少し長い。**間違えたあとの 0 社目は、試作 v3 がさっきのカードも出しているため 1283〜1300 px (約 2 画面)** で、収まらない。むずかしいの最初の 0 社目は 2418〜2585 px (3.8〜4 画面。縦に流す。design-v3 §3.2 #141-2・measurements.md v3-1)。→ **設計**: 掲示を 1 行にし、間違えたあとはさっきのカードを出さず文だけにする (上の表)。それで 320×640 のやさしいの足元が札の帯に隠れないかは、#187 で測る (**未確認**)。
- 前の版の「やさしいの 0 社目は 1 画面に収まる (測った)」は誤りだった (レビューで指摘を受けた。n 枚目のカードを測った値を 0 社目に読み替えていた)。
- **タイトルと難易度を 1 画面にする** (**設計**): design-v2 §3.1 は別画面。1 画面にして、始めるまでの操作を 2 回から 1 回にする。**状態機械 (`src/domain/game.ts`) は変えない**。対応: ① 合成した画面は、状態 `title` でも `difficulty` でも**同じ画面**を描く。② `title` で難易度のボタンを押したら、`START` を続けて `PICK` を送る (UI の合成。#187 で足す)。③ `difficulty` で押したら `PICK` だけ。④ クリアの「別の難易度」は `TO_DIFFICULTY` (描くのは同じ画面)。「記録」からの戻りは、来た状態へ。**未確認**: 2 つの難易度が並ぶと、「どっちを選ぶか」で迷うか (人の確かめ)。
- **途中でタイトルへ戻る道**: 0 社目の上端に、小さな「難易度を変える」を置く。状態機械は `TO_DIFFICULTY` を不正解の `revealed` と `cleared` でしか受け付けない (`src/domain/game.ts`) ので、0 社目では **`TO_TITLE` を送る** (`title` 以外のどの状態からも受け付ける。合成した画面は `title` でも同じに描くので、見た目は同じ)。クリアの「別の難易度」だけが `TO_DIFFICULTY`。記録の画面はタイトルの上の画面で、「戻る」だけを置く (難易度を変える道は要らない)。押し間違えた難易度を、0 社目ですぐ替えられる。**n 社目と答え合わせには置かない** (進行を失う押し間違えを防ぐ。8 社の途中でやめたい人は、ページを読み直せば最初に戻る)。**未確認**: 8 社の途中で難易度を変えたい人が、ページを読み直す手間で離脱するか (人の確かめ)。
- **記録は、既存の記録 (`src/domain/records.ts` の `best`・`clears`・`kinds`) を見せるだけ**で、新しい保存は足さない (**確かめた**: `DifficultyRecord` に 3 つともある)。ブラウザ内 (localStorage) だけに保存する (今のまま)。
- 流れの細部 (不正解の約 1 秒・0 社目へ自動で戻る・クリアの「もう一度」) は design-v2 §3.1 のとおり。

## 3. 遊びの手触り: 3 案を、遊び手の目で比べる

**前提** (文書にある。research.md §1): 8 番出口は、失敗が痛い (全てを失う) のに離脱しにくい。理由は**再開が一瞬で、1 周が短い**から (research.md の「離脱しにくさ」の行。TechRadar・Siliconera の評)。反対に「見逃すと最初からで苛立つ」(Nintendo Life) という評もある。待ち時間は離脱の主因になりうる (**導いた**: 続編の試作で「座る動作が面倒」として捨てたこと)。つまり、**続ける理由は「もう 1 回やれば行けそう」(再開の速さと、納得できる負け方)、離脱する瞬間は「理不尽に負けた」「待たされた」「何をするか分からない」**。この物差しで比べる。

| | 案 A 紙を送る (ほぼ説明のない、軽い判定) | **案 B 押して確かめる (採用)** | 案 C 張り詰める (進行で画面が変わる) |
| --- | --- | --- | --- |
| 中身 | 札を押すと、伝票が上へ送られて次の伝票が来る。印は無い | 札を押すと、**朱の押印が 1 回重く落ちる** (強い動きはこの 1 回だけ)。間違えると伝票が差し戻される | 点検欄が埋まるほど、紙の色・罫の太さ・伝票の傾きが変わって 7・8 社目が張り詰める。判定は札を押すだけ |
| 続ける理由 | テンポが速い。ただし手ごたえが薄く、「やった」が残らない | **押した手ごたえ**が残る。押印は「判定した」の確かな合図で、答え合わせへの間 (一拍) になる | 後半の緊張が続ける理由になる (8 番出口の緊張。research.md §1 の「緊張」の行) |
| 離脱する瞬間 | 判定の合図が薄いので、「押せたのか」が不安 | 「印」の語が分からない (人間が言った)。→ **印の字を札と同じ言葉にして解消** | 画面が変わる分、説明が要る・読みづらさが増す。7・8 社目で伝票の傾きが読みにくいと、**正しく読んだ人が不正解になる**危険 (charter の失敗 1・2 に近い) |
| 8番出口の芯 | ① 反復は強い。④ 再開の速さは同じ | ① 反復・④ 一瞬の再開・⑥ 説明は掲示だけ。判定を 1 つの操作にする (②) | ⑤ 進むほど難しい、の演出的な写し |
| 実装・測定 | 軽い | DESIGN.md の方向 (責任者の決定) と同じ。試作 v3 に押印がある | 動きの種類が増え、「動きを減らす設定」「18 px・コントラスト」の確かめが増える |
| 要件・制約との相性 | ○ | ○ (動きは押印 1 回。DESIGN.md の One Press Rule) | △ (「強い動きは押印の 1 回だけ」を破る) |

**選んだ理由 (案 B)**: ① 離脱の瞬間「何をするか分からない」を、**押印の字を札の言葉にそろえる**ことで解消できる (案 B は直せる。案 A は合図が薄いままで、案 C は説明が増える)。② 動きを押印 1 回に絞るので、「動きを減らす設定」と読みやすさの確かめが少なくて済む (**導いた**)。③ 責任者が決めた方向 (仕訳伝票・押印。DESIGN.md) を変えない。
**案 B に足したもの** (どれも動きでなく、言葉と配置):
- **あと N 社**: 点検欄の隣に「n 社目 / あと N 社」と言う (8 社の目標を、数字でも見せる)。7 社目は「あと 2 社」・8 社目は「ラスト」。根拠は、目標に近づくほど努力が増える「目標勾配」の研究: Kivetz・Urminsky・Zheng (2006)「The Goal-Gradient Hypothesis Resurrected: Purchase Acceleration, Illusionary Goal Progress, and Customer Retention」Journal of Marketing Research 43(1), pp. 39–58 (DOI 10.1509/jmkr.43.1.39。**2026-11-09 に OpenAlex から抄録を取得して確かめた**)。抄録の原文: 「participants in a real café reward program purchase coffee more frequently the closer they are to earning a free coffee」「Internet users who rate songs in return for reward certificates visit the rating Web site more often, rate more songs per visit, and persist longer in the rating effort as they approach the reward goal」。**限界**: 買い物と評価サイトの実験で、**ゲームの離脱を測ったものではない**。「あと N 社」の語が離脱を減らすかは**未確認** (人の確かめ)。
- **クリアの完了票**: 8 社の社章を並べ、「見つけた異変 n / N」を出す。「別の難易度」を提案する (やさしいをクリアしたあとはむずかしいを、1 行で)。
- **自己ベスト**: 間違えて 0 社目へ戻るとき「最高 N 社目」を小さく出す (records の `best`・`bestBefore`)。
**案 C の「進行で張り詰める」は、今回は入れない** (人間が言っていない追加要素で、読みづらさの危険がある)。案 C を試したくなったら、追加オプションとして出す。

## 4. 離脱しにくさ: 離脱する瞬間と、対策・確かめ方
